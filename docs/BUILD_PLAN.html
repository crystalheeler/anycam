B47Ready to buildPriority

The Microseven never plays live: go2rtc builds a broken video description from it

Why
CrystalHeeler, 2026-10-06 evening, test system A, Chrome chrome://media-internals: with the camera on H.265, the card and Enhanced View players fail with "Invalid video decoder config: codec: hevc ... coded size: [4,0]" and "[0,127]"; with the camera switched to H.264 main profile, "Unrecognized video codec profile". Both are CHUNK_DEMUXER_ERROR_APPEND_FAILED: the MSE init segment go2rtc builds from the camera's parameter sets is invalid. AnyCam's classic view (ffmpeg) decodes the same stream at 3840x2160. Known go2rtc behaviour with cameras that send bad or missing parameter sets in the SDP (go2rtc issues 2361 and 2529); the documented workaround is an ffmpeg copy source (ffmpeg:rtsp://...#video=copy), which rebuilds the parameter sets without decoding. AnyCam runs go2rtc without its ffmpeg module (api, ws, rtsp, webrtc, mp4)
Next step
Proposed, for agreement: for this camera (or any camera whose live player fails this way), give go2rtc an ffmpeg copy source; this needs the ffmpeg module, or AnyCam's own ffmpeg pushing a copy into go2rtc's RTSP server. Field test needs the camera CrystalHeeler, 2026-10-06: CrystalHeeler chose design A (go2rtc's ffmpeg module, an ffmpeg copy source for this camera only; every other camera keeps its direct source). Camera: Microseven MYM74K-HX, firmware v1.0.12; RTSP port 554, RTSP authentication on, RTMP on port 1935 (VLC with the usual Hipcam address rtmp://camera:1935/flash/11:user:password failed, 2026-10-06; the address format may differ on this model; not pursued). Left on H.264 main profile, 20 fps, I-frame interval 20, 8,192 kbps CBR. The build also logs go2rtc's own view of a stream (codecs, description) when a live player fails, so the first remote test gives data. Field test: update in place, no uninstall (a reinstall rescans and re-checks the password)
